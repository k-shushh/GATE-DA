Think like Python

01 · From a file to a running program

A program is a sequence of instructions that transforms input into output. An algorithm is the method; Python is one language for expressing it. Before writing code, state the input, the expected result, and what counts as a valid input.

Save code as a .py file and run it with python filename.py (or py filename.py on Windows). A REPL evaluates one interaction at a time; a script runs top to bottom. In a script, an expression alone does not display its value: use print. Our browser lab runs real Python in a separate worker.

Indentation defines blocks. Use four spaces consistently, a colon before an indented suite, and # for a comment. Names are case-sensitive; total and Total differ. Choose meaningful identifiers and avoid shadowing built-ins such as list, str and sum. A newline usually ends a statement; brackets permit readable multi-line expressions.

Syntax errors prevent parsing. Runtime errors happen while executing valid syntax. Logic errors produce the wrong result without an exception. Debug by first predicting the state, then comparing it to observed output; do not randomly edit until a test passes.

price = 120
quantity = 3
subtotal = price * quantity
discount = 0.10
total = subtotal * (1 - discount)
print(f"Total: {total:.2f}")

Output:

Total: 324.00

First multiply 120 by 3. Then apply the remaining fraction 0.9. The f-string formats the numeric value with two digits after the decimal point; formatting does not change the stored number.

10% is written as 0.10, not 10. Python does not infer units such as rupees or percentages.

Your turn: Change the quantity to 5 and discount to 20%. Predict the total before running.

02 · Names, objects and types

A name refers to an object; it is not a permanently typed storage box. x = 3 binds x to an integer object. x = "three" later rebinds that name to a string. Objects have types; names can refer to different types over time. Assignment itself does not copy an object.

The main scalar types are int (arbitrary precision within memory limits), float (binary floating point), bool (True or False), complex and NoneType. None is a singleton used to represent absence, not zero or an empty string. Test it with is None.

Use type(x) to inspect a type and isinstance(x, T) for a type relationship. bool is a subclass of int, so isinstance(True, int) is True. Numeric conversions are explicit when needed: int("12") is 12; int("12.5") fails; int(-2.9) is -2 because conversion truncates toward zero.

Parallel assignment evaluates the right side before binding the left side. This makes a, b = b, a a correct swap. Two names referring to the same mutable object matter later: changing that object through either name is visible through both.

a = 7
b = a
a = a + 1
print(a, b)
a, b = b, a
print(a, b)
print(type(3).__name__, int(-2.9), None is None)

Output:

8 7
7 8
int -2 True

a + 1 creates a new integer value and rebinds a. b still refers to 7. Swapping then uses the old pair of values simultaneously.

Do not use is to compare numeric or string values. Object reuse is an implementation detail; use == for equal values.

03 · Arithmetic and the negative-number trap

Use +, -, *, /, //, %, and ** for addition, subtraction, multiplication, true division, floor division, remainder, and exponentiation. True division of integers produces a float. Floor division rounds the quotient toward negative infinity; int conversion instead truncates toward zero.

For nonzero b, integer division obeys a == (a // b) * b + a % b. The remainder is zero or has the sign of b. Therefore -7 // 3 is -3 and -7 % 3 is 2. This identity is safer than memorising a rule from another language.

Exponentiation associates right-to-left: 2 ** 3 ** 2 is 2 ** 9. Unary minus on the left is applied after exponentiation: -2 ** 2 is -4. Parenthesise intentionally. Multiplication/division bind before addition/subtraction; operators at the same arithmetic level usually associate left-to-right.

Binary floats approximate most decimal fractions. Do not assume 0.1 + 0.2 == 0.3. Use math.isclose for measured quantities with suitable tolerances, Decimal constructed from strings for decimal arithmetic, or Fraction for exact rational arithmetic. Python integers do not have fixed 32-bit overflow, but huge integer operations are not constant-time.

import math
print(-7 // 3, -7 % 3)
print((-7 // 3) * 3 + (-7 % 3))
print(-2 ** 2, (-2) ** 2, 2 ** 3 ** 2)
print(0.1 + 0.2 == 0.3, math.isclose(0.1 + 0.2, 0.3))

Output:

-3 2
-7
-4 4 512
False True

The quotient -3 and remainder 2 reconstruct -7. Parentheses change whether the minus sign is part of the base. isclose checks approximate equality rather than identical binary representations.

/ and // are not interchangeable. Also, ^ is bitwise XOR, not exponentiation.

04 · Comparisons, truth and bits

Comparisons ==, !=, <, <=, > and >= produce Booleans. Chained comparisons such as 0 <= x < 10 express a range. Membership in asks whether a container contains a value (for a dict, it tests keys). is asks whether two references identify the same object.

False values include False, None, numeric zero and empty containers. Nonempty strings are true, including "False" and "0". and and or short-circuit and return an operand, not necessarily a bool: [] or [1] returns [1]; 0 and dangerous_call() returns 0 without making the call.

A practical precedence ladder is: indexing/calls; exponentiation; unary arithmetic; multiplication/division/remainder; addition/subtraction; shifts; bitwise &, ^, |; comparisons and membership/identity; not; and; or. Use parentheses for clarity rather than relying on obscure precedence.

For integers, & intersects set bits, | combines them, ^ toggles differing bits, and << or >> shifts. For nonnegative x, x << k equals x * 2**k. Python signed integers behave as though they have infinitely extended sign bits: ~x equals -x-1 and -3 >> 1 is -2. Bitwise & is not a replacement for Boolean and.

print(bool("False"), bool([]))
print(0 or 7, 3 and 8)
print(0 < 4 < 5)
print(6 & 3, 6 | 3, 6 ^ 3, 1 << 3)
print(~5, -3 >> 1)

Output:

True False
7 8
True
2 7 5 8
-6 -2

6 is binary 110 and 3 is 011. AND keeps 010, OR yields 111, XOR yields 101. These correspond to 2, 7, and 5.

A fallback such as value or default replaces all false values, including legitimate zero. Use an explicit None check when zero must survive.

Control the flow

01 · Decisions and input contracts

An if/elif/else chain selects the first true branch and skips the remaining branches. Separate if statements are independent and may all execute. Put the most specific conditions before more general ones when their ranges overlap.

input() returns a string, even when the user types digits. Parse with int or float only after deciding what inputs you accept. Our lab has an input-lines box: one line is consumed by each input call. For self-contained examples we often use literal inputs so the behaviour is reproducible.

Express preconditions explicitly. A percentage score should usually lie between 0 and 100; reject invalid values rather than silently classifying them. Boundary values deserve separate tests: just below, equal to, and just above each threshold.

A conditional expression is value_if_true if condition else value_if_false. It is useful for one short choice; deeply nested conditional expressions obscure logic. match/case (Python 3.10+) performs structural pattern matching, not arbitrary Boolean selection; ordinary if statements are enough for this course.

score = 78
if not 0 <= score <= 100:
    print("Invalid")
elif score >= 80:
    print("Distinction")
elif score >= 60:
    print("Pass")
else:
    print("Revise")
print("even" if score % 2 == 0 else "odd")

Output:

Pass
even

78 misses the 80 threshold, reaches the 60 threshold, and prints Pass. Only one branch runs. The separate expression then classifies parity.

if x == 1 or 2 is almost always wrong: it means (x == 1) or 2 and is always truthy. Use x in (1, 2).

02 · for, range and while

A for loop takes successive values from an iterable. range(start, stop, step) is a compact sequence of integers excluding stop. Defaults are start=0 and step=1; step cannot be zero. A negative step is needed to count down. range(5, 0, -2) yields 5, 3, 1.

A while loop repeats while its condition is true. Identify the initial state, condition, body and update. Prove that each iteration makes progress toward termination. A missing update is a common cause of infinite loops.

An accumulator combines values (sum, product, maximum); a counter counts events. Choose the initial value from the operation identity: 0 for addition, 1 for multiplication. For a maximum over potentially negative numbers, initialise from the first value or use None, not automatically 0.

An invariant is a statement that stays true before each iteration. In a running sum over a sequence, total equals the sum of all elements already visited. Initially no elements are visited and total=0; each update preserves the claim; at termination it proves correctness.

total = 0
for number in range(1, 6):
    total += number
    print(number, total)
n = 13
bits = 0
while n > 0:
    bits += 1
    n //= 2
print("bits:", bits)

Output:

1 1
2 3
3 6
4 10
5 15
bits: 4

The first loop adds 1 through 5. The while loop visits n=13,6,3,1 before reaching zero, giving four binary digits.

range endpoints are excluded. range(1, n) does not include n. An empty range executes the body zero times.

03 · break, continue, else and nested loops

break exits the nearest enclosing loop. continue skips the rest of the current iteration and proceeds to the next one. pass does nothing; it is a syntactic placeholder, not a skip instruction.

A loop else runs when the loop finishes without break, including when the loop executes zero times. It is useful for unsuccessful searches. A return inside a function exits the whole function and therefore does not execute the loop else.

For nested loops, draw one row per outer-loop value and count inner iterations. If the inner loop runs i times for i=0..n-1, the total is n(n-1)/2, not n. A break inside the inner loop does not exit the outer loop.

Avoid changing list length while iterating over it: shifted positions can be skipped. Construct a filtered list or iterate over a deliberate copy. If updating a while-loop variable, ensure a continue cannot accidentally bypass the update.

n = 17
for divisor in range(2, int(n ** 0.5) + 1):
    if n % divisor == 0:
        print("composite")
        break
else:
    print("prime" if n >= 2 else "not prime")
count = 0
for i in range(4):
    for j in range(i):
        count += 1
print(count)

Output:

prime
6

No divisor 2, 3 or 4 divides 17, so the else executes. The nested-loop counts are 0+1+2+3=6. For very large integers, math.isqrt is safer than a floating-point square root.

The else belongs to the loop at the same indentation, not the inner if.

Work with text

01 · Strings and slicing

A str is an immutable sequence of Unicode code points. Index 0 selects the first element; -1 selects the last. Indexing outside the sequence raises IndexError. len counts code points, which need not equal the number of visually perceived characters.

s[start:stop:step] selects indices beginning at start and ending before stop. For positive steps, omitted bounds cover left to right; for negative steps they cover right to left. Slices clip out-of-range bounds and can be empty. A zero step raises ValueError.

s[::-1] reverses the sequence. s[-1:0:-1] includes the last character and excludes index 0. The omitted stop in s[::-1] is not the same as an explicit -1 in s[:-1:-1]; explicit negative indices are normalised first.

Strings cannot be edited in place. To replace a character, construct a new string from pieces. The original string is unaffected. Raw string literals make backslashes easier to write, but cannot end in a single unescaped backslash. Escape sequences such as \n represent one newline character.

s = "PYTHON"
print(s[0], s[-1])
print(s[1:5:2])
print(s[::-1])
print(s[-1:0:-1])
print(s[99:], s[:99])

Output:

P N
YH
NOHTYP
NOHTY
 PYTHON

Indices 1 and 3 spell YH. Reversal visits 5,4,3,2,1,0. Excluding index 0 omits the P. The last print begins with a space because its first argument is an empty string.

A slice never changes the source string. Negative step does not automatically reverse arbitrary start/stop choices.

02 · Methods, parsing and formatting

strip removes specified characters from the two ends, not a substring from the middle. split() with no separator collapses runs of whitespace; split(",") treats each comma as a delimiter and can preserve empty fields. separator.join(strings) assembles strings with separators.

lower and casefold support case normalisation; casefold is more aggressive for Unicode comparisons. startswith, endswith, find, count and replace support common text tasks. find returns -1 when absent; index raises ValueError. Never treat a find result directly as Boolean because 0 is a valid found index.

f-strings evaluate expressions inside braces. Use format specifications such as :.2f for two decimal places or :>8 for right alignment. repr exposes quotes and escape characters, while str produces a user-facing representation.

Parsing is a pipeline: normalise, split, validate, convert, then compute. Do not use eval to parse untrusted data. For structured formats use csv or json. CSV fields can contain quoted commas, so naive split(",") is appropriate only when the input contract excludes them.

raw = "  Alice, 82, 91, 87  "
parts = raw.strip().split(",")
name = parts[0].strip()
marks = [int(piece) for piece in parts[1:]]
mean = sum(marks) / len(marks)
print(f"{name}: {mean:.2f}")
print("-".join(["DA", "Python", "2027"]))

Output:

Alice: 86.67
DA-Python-2027

The first field remains text; the other fields become integers. The average is 260/3. Formatting rounds the displayed result without modifying mean.

strip("ab") removes any a or b at either end; it does not remove exactly the prefix "ab". Use removeprefix for that purpose.

03 · Text algorithms and edge cases

A palindrome reads identically forwards and backwards. First define the comparison rule: are spaces, punctuation and letter case significant? The preprocessing policy is part of the algorithm, not an afterthought.

A character histogram maps each character to a count. Comparing histograms tests whether two strings are anagrams under the chosen normalisation. Sorting also works but usually costs O(n log n), versus expected O(n) counting with a hash table.

A two-pointer palindrome check advances from both ends and can stop at the first mismatch. It uses O(1) extra space on the existing string. Constructing s[::-1] uses O(n) additional space. Normalisation may itself require O(n) space.

For repeated concatenation of many strings, collect pieces in a list and join once. Repeatedly creating a larger immutable string can require quadratic total copying. Always test empty text, one character, repeated characters, and mixed case.

def palindrome(text):
    clean = "".join(c.casefold() for c in text if c.isalnum())
    left, right = 0, len(clean) - 1
    while left < right:
        if clean[left] != clean[right]:
            return False
        left += 1
        right -= 1
    return True
print(palindrome("Never odd or even"))
print(palindrome("Python"))

Output:

True
False

The first string normalises to neveroddoreven. Each mirrored pair matches. Python fails on its first pair, p and n.

The empty string is usually a palindrome under the standard definition; document that decision rather than allowing a test to surprise you.

04 · Unicode, bytes and safe conversion

Text and binary data are different abstractions. str represents Unicode code points; bytes represents integers from 0 to 255. Encoding turns text into bytes using a named encoding such as UTF-8. Decoding reverses that operation when the bytes are valid for the encoding.

A character can occupy multiple bytes in UTF-8. Therefore len(text) and len(text.encode("utf-8")) can differ. Indexing bytes gives an integer; slicing bytes gives bytes. bytearray is a mutable binary sequence.

ord converts a one-character string to its code point; chr performs the inverse. Alphabetical order in Python strings is based on code-point lexicographic comparisons, not human-language collation. Visually identical text may use different Unicode sequences; unicodedata.normalize helps when a defined normalisation policy is needed.

Specify encoding explicitly for portable file processing. A UnicodeDecodeError means the bytes do not satisfy the chosen decoding rules. Ignoring errors can silently discard data; prefer detecting the actual encoding or reporting the problem. JSON and CSV parsing happen after bytes have been decoded into text.

text = "café"
data = text.encode("utf-8")
print(len(text), len(data))
print(data[0], data.decode("utf-8") == text)
print(ord("A"), chr(66))
mutable = bytearray(b"abc")
mutable[0] = 65
print(bytes(mutable))

Output:

4 5
99 True
65 B
b'Abc'

The final character occupies two bytes in UTF-8, so four code points use five bytes. The first byte is 99, the code for c. Changing bytearray position zero to 65 changes a to A.

Do not assume a character is one byte, or that len counts visual grapheme clusters.

Lists, tuples & memory

01 · Sequence operations and list methods

A list is a mutable ordered sequence; a tuple is an immutable ordered sequence. Both support indexing, slicing, iteration, membership, concatenation and repetition. A one-element tuple needs a comma: (5,) is a tuple, (5) is an integer.

append(x) adds one object; extend(iterable) appends its elements. insert(i,x) inserts before index i. pop(i) removes and returns an item; remove(x) removes the first equal value. del can delete an index or slice. clear empties the list.

sort and reverse mutate a list and return None. sorted(iterable) creates a new list. Slicing creates a new outer sequence. Slice assignment such as a[1:3] = [9] can change list length; extended-slice assignment needs the same number of replacement elements as selected positions.

Sequence unpacking requires matching lengths unless a starred target absorbs remaining elements: first, *middle, last = values. Membership in a list typically scans; indexing is constant-time in the usual Python list model.

a = [1, 2]
a.append([3, 4])
print(a)
b = [1, 2]
b.extend([3, 4])
print(b)
removed = b.pop(1)
result = b.reverse()
print(removed, b, result)
print((5,), type((5)).__name__)

Output:

[1, 2, [3, 4]]
[1, 2, 3, 4]
2 [4, 3, 1] None
(5,) int

append keeps the nested list as one element. extend iterates through its two values. pop(1) removes 2; reverse changes b and returns None.

a = a.sort() loses the reference to the sorted list by rebinding a to None.

02 · Aliasing, shallow and deep copies

a = [1,2]; b = a gives two names for one list. b.append(3) changes the shared object. b = [9] instead rebinds b to a different object and leaves a unchanged. Distinguish an arrow change (rebinding) from an object change (mutation).

b = a[:] or a.copy() creates a new outer list, but nested objects remain shared. A shallow copy is sufficient when inner objects will not be mutated or are immutable. deepcopy recursively copies nested structure while tracking objects already copied.

Equality == asks whether values compare equal; identity is asks whether the objects are the same. A shallow copy usually satisfies a == b and a is not b initially. Independent outer lists can still refer to identical inner objects.

With lists, += generally extends the existing object, whereas a = a + values creates a new list and rebinds a. Aliases observe the first operation but continue pointing to the old list after the second. These details explain many Python output questions.

from copy import deepcopy
a = [[1], [2]]
b = a[:]
c = deepcopy(a)
b[0].append(9)
b[1] = [7]
print(a)
print(b)
print(c)
print(a is b, a[0] is b[0])

Output:

[[1, 9], [2]]
[[1, 9], [7]]
[[1], [2]]
False True

b[0].append changes the inner list shared with a. b[1]=[7] replaces only one reference in b. c contains separately copied nested lists.

A shallow copy protects the outer container, not arbitrary nested objects.

03 · Matrices and nested-container traps

A matrix can be represented as a list of row lists. matrix[r][c] first selects a row, then a column. Define whether ragged rows are permitted; many matrix algorithms require equal row lengths.

[[0] * columns] * rows repeats references to the same row. Mutating one row through any position appears in every row. [[0] * columns for _ in range(rows)] evaluates the inner expression separately for each row and creates independent row objects.

Tuple immutability prevents replacing its element references, but a tuple may contain a mutable list whose contents can change. Consequently not every tuple is hashable: a tuple containing a list cannot be a dict key.

For a rectangular matrix, transpose swaps row and column positions. zip(*matrix) groups corresponding row elements and returns tuples; by default it stops at the shortest row. Use explicit shape validation if dropping values would be a bug.

bad = [[0] * 3] * 2
good = [[0] * 3 for _ in range(2)]
bad[0][1] = 5
good[0][1] = 5
print(bad)
print(good)
t = ([1], 2)
t[0].append(3)
print(t)
print(list(zip(*[[1, 2], [3, 4]])))

Output:

[[0, 5, 0], [0, 5, 0]]
[[0, 5, 0], [0, 0, 0]]
([1, 3], 2)
[(1, 3), (2, 4)]

Both entries in bad reference the same row. good has two rows. Mutating the list inside t changes the list, not which object the tuple points to.

[[0]] * n repeats references, not independent lists. Multiplication is safe for the row of immutable integers, but not for the outer repeated row.

Dictionaries & sets

01 · Dictionaries and hashable keys

A dict maps unique keys to values. A new assignment to an existing key replaces its value; it does not create another entry. Modern Python preserves insertion order. Replacing a value does not move its key; deleting and reinserting does.

Keys must be hashable: their hash must remain stable and equality must agree with hashing. Integers, strings and tuples of hashable elements work. Lists, dicts and mutable sets do not. frozenset is immutable and hashable. True, 1 and 1.0 compare equal and address the same dictionary key.

d[k] raises KeyError if absent. d.get(k, default) returns a fallback without inserting. setdefault inserts a fallback when absent. in d checks keys; d.values() and d.items() expose values and key-value pairs. These views reflect later changes.

A hash table first uses a hash to narrow down where a key might be, then checks equality. Collisions are possible and must be resolved. Lookup, insertion and deletion are expected O(1) under suitable hashing, but can be O(n) in the worst case; hashing a long fresh string itself costs work.

counts = {}
for word in ["data", "python", "data"]:
    counts[word] = counts.get(word, 0) + 1
print(counts)
print("python" in counts, 2 in counts)
d = {True: "first", 1: "second", 1.0: "third"}
print(len(d), d[True])

Output:

{'data': 2, 'python': 1}
True False
1 third

Each repeated word updates a count. True, 1, and 1.0 identify equal numeric keys, so the final dict has one entry with the last value.

get does not insert. Also, adding or removing keys while iterating a dictionary can raise RuntimeError; iterate a copy or collect changes first.

02 · Sets and choosing the right container

A set stores distinct hashable elements and supports membership, union |, intersection &, difference -, and symmetric difference ^. Its iteration order is not a language-level insertion-order guarantee. Sort a set when you need deterministic ordered output.

{} creates an empty dictionary; set() creates an empty set. add inserts one element; update inserts elements from an iterable. remove raises KeyError when missing; discard does not. A subset test <= includes equality; a proper subset test < excludes equality.

Use a list for ordered sequences with duplicates, tuple for a fixed record, dict for key-to-value association, and set for uniqueness and membership. Order-preserving deduplication can use dict.fromkeys(values) when the values are hashable.

A set trades memory for fast expected membership. Building a set of n elements is expected O(n); repeatedly converting a list into a set inside a loop defeats the intended benefit. For unhashable records, choose a hashable key or a different comparison method.

a, b = {1, 2, 3}, {3, 4}
print(sorted(a | b))
print(sorted(a & b))
print(sorted(a - b))
print(sorted(a ^ b))
print(list(dict.fromkeys([3, 1, 3, 2, 1])))

Output:

[1, 2, 3, 4]
[3]
[1, 2]
[1, 2, 4]
[3, 1, 2]

Intersection keeps only 3. Symmetric difference keeps elements in exactly one set. dict.fromkeys retains the first insertion order of unique keys.

Do not answer a question with a fixed set print order unless the question explicitly imposes one.

03 · Counting and grouping patterns

Counting stores one aggregate per key. Grouping stores a collection per key. collections.Counter handles counts; defaultdict(list) creates an empty list when a missing key is indexed. Ordinary dict plus setdefault is another option.

The two-sum pattern scans values while storing what has been seen. For each x, check whether target-x occurred earlier; then insert x. Checking before insertion prevents reusing the same position. This gives expected O(n) time and O(n) space.

To group anagrams, choose a canonical key: a sorted character tuple, or a fixed-alphabet frequency tuple. The key must preserve exactly the equivalence relation you intend. Case and punctuation handling must be explicit.

When using a mutable default value, create a new object for each group. dict.fromkeys(keys, []) gives every key the same list, much like repeated matrix rows. A comprehension {k: [] for k in keys} creates independent lists.

from collections import Counter, defaultdict
print(Counter("banana")["a"])
groups = defaultdict(list)
for name, team in [("Asha", "red"), ("Dev", "blue"), ("Ira", "red")]:
    groups[team].append(name)
print(dict(groups))
def two_sum(values, target):
    seen = {}
    for i, x in enumerate(values):
        if target - x in seen:
            return seen[target - x], i
        seen[x] = i
    return None
print(two_sum([3, 3, 8], 6))

Output:

3
{'red': ['Asha', 'Ira'], 'blue': ['Dev']}
(0, 1)

The first 3 is stored at index 0; when the second 3 arrives, its complement has already been seen. The two indices are distinct.

Do not initialise all grouping buckets with the same shared list.

Functions, scope & recursion

01 · Parameters, return and contracts

A function packages a reusable computation. Define inputs, output, side effects and invalid-input behaviour. def creates a function object and binds its name; the body runs when called. return ends the call and sends a value to its caller.

A function without an executed value-return returns None. Printing and returning are different: printing is an output side effect; return makes a value available for further computation. Multiple return values are usually a tuple that the caller unpacks.

Parameters are local names bound to the argument objects. Mutating a passed list can affect the caller; rebinding the parameter cannot rebind the caller name. This model is often called call by object sharing; it is more precise than saying all arguments are copied.

A pure function gives the same output for the same inputs without changing external state. Pure cores are easier to test. Keep input parsing and printing near the edges of a program and computation inside functions.

def summary(values):
    if not values:
        raise ValueError("at least one value required")
    return min(values), max(values), sum(values) / len(values)
low, high, mean = summary([2, 4, 9])
print(low, high, mean)
def touch(items):
    items.append(3)
    items = [99]
a = [1, 2]
print(touch(a))
print(a)

Output:

2 9 5.0
None
[1, 2, 3]

touch mutates the shared list, then rebinds only its local name. Its implicit return is None. summary returns a tuple of three values.

A function that prints a result is not automatically usable as a numeric expression.

02 · Arguments and the mutable-default trap

Arguments may be positional or named. Defaults are evaluated when the def statement executes, not on every call. A mutable default can therefore retain modifications across calls. Use None as a sentinel and create a fresh object inside the function.

*args collects additional positional arguments into a tuple; **kwargs collects additional keyword arguments into a dict. At a call site, *sequence and **mapping unpack arguments. Positional-only parameters precede /; keyword-only parameters follow * or *args.

A default is a reference to the object at definition time. Reassigning a separate name later does not update that reference. Passing the same parameter both positionally and by keyword raises TypeError.

Prefer an explicit, small signature over accepting arbitrary arguments without validation. Document whether a function mutates inputs and what types it expects. Type annotations help readers and tools but do not automatically enforce types at runtime.

def collect_bad(x, bucket=[]):
    bucket.append(x)
    return bucket
print(collect_bad(1))
print(collect_bad(2))
def collect(x, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(x)
    return bucket
print(collect(1), collect(2))
def scale(x, *, factor=2):
    return x * factor
print(scale(3, factor=4))

[1]
[1, 2]
[1] [2]
12

collect_bad reuses its one default list. collect creates a new list on each omitted-bucket call. factor is keyword-only.

The bad example is intentionally wrong for independent collections; shared defaults can be deliberate, but should not be accidental.

03 · Scope, closures and name lookup

For ordinary function bodies, name lookup follows Local, Enclosing function scopes, Global module scope, and Built-ins (LEGB). Assignment in a function normally makes that name local throughout the function, even before the assignment executes.

Reading a local name before it has been bound raises UnboundLocalError. global targets a module-level name; nonlocal targets an already existing binding in an enclosing function. Neither is needed merely to mutate an object reached through a name.

A closure retains access to its enclosing bindings after the outer function returns. It does not freeze the values of loop variables at creation time. Several lambdas can therefore all observe the final loop value.

Capture a value deliberately with a default parameter, or build each closure in a helper call with a distinct local binding. Avoid unnecessary globals: explicit parameters make dependencies visible and tests independent.

x = 10
def outer():
    count = 0
    def step():
        nonlocal count
        count += 1
        return count
    return step
counter = outer()
print(counter(), counter(), x)
late = [lambda: i for i in range(3)]
early = [lambda i=i: i for i in range(3)]
print([f() for f in late])
print([f() for f in early])

Output:

1 2 10
[2, 2, 2]
[0, 1, 2]

counter retains one count binding and increments it twice. The late lambdas share the loop binding; the early lambdas each store a default value.

A name is not automatically global because it has not yet been assigned on the current execution path. Assignment anywhere in the function normally classifies it as local.

04 · Recursion: descent, base case, unwind

A recursive function solves a problem using smaller instances of itself. You need a base case, a reduction that reaches it, and a rule that combines the smaller answer. A base case alone is not enough if some inputs move away from it.

Every active call has its own local parameters and pending work. For factorial(4), the multiplication by 4 waits for factorial(3), which waits for factorial(2), and so on. Returning from the base case unwinds these pending operations in reverse order.

Distinguish printing before a recursive call from printing after it. Before-call output appears during descent; after-call output appears during unwind. Draw frames and return values rather than trying to simulate everything mentally.

A linear-depth recursive routine uses O(n) call-stack space even if each frame has only a few variables. Python has a recursion limit and does not generally eliminate tail calls. Iteration is preferable for very deep simple recurrences.

def factorial(n):
    if n < 0:
        raise ValueError("n must be nonnegative")
    if n == 0:
        return 1
    return n * factorial(n - 1)
print(factorial(4))
def trace(n):
    if n == 0:
        return
    print("enter", n)
    trace(n - 1)
    print("leave", n)
trace(3)

Output:

24
enter 3
enter 2
enter 1
leave 1
leave 2
leave 3

factorial reaches 0 then returns 1, 1, 2, 6 and 24. trace prints enter on descent and leave on unwind.

Do not forget the recursive call consumes stack space. Raising the recursion limit is not a substitute for choosing an appropriate algorithm.

05 · Repeated work and memoisation

A branching recursion can solve the same subproblem many times. Naive Fibonacci computes fib(n-1) and fib(n-2), whose recursion trees overlap. Its running time grows exponentially, although the maximum stack depth is only O(n).

Memoisation stores answers by input so each distinct subproblem is computed once. functools.cache provides an unbounded memo table for hashable arguments. Cached functions should be deterministic for their arguments; mutable external state can make cached answers stale.

Bottom-up dynamic programming computes smaller results first. Fibonacci needs only the previous two values, so an iterative implementation can use O(1) auxiliary variables. For huge integers, arithmetic bit costs and output size still grow.

Euclid’s gcd recursion uses gcd(a,b)=gcd(b,a%b), ending at b=0. Its argument shrinks rapidly; it is an example where recursive depth is logarithmic rather than linear. Recursion cost depends on the actual reduction and branching, not the presence of def calling itself.

from functools import cache
@cache
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
print(fib(10))
def fib_loop(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
def gcd(a, b):
    return abs(a) if b == 0 else gcd(b, a % b)
print(fib_loop(10), gcd(48, 18))

Output:

55
55 6

The memoised function evaluates each argument from 0 to 10 once. The loop advances the pair (F(k),F(k+1)). Euclid follows (48,18)→(18,12)→(12,6)→(6,0).

A cache is useful only when repeated calls reuse results; it also consumes memory and requires hashable inputs.

Write expressive Python

01 · Comprehensions and iteration helpers

A comprehension describes a new collection from an iterable: [expression for x in source if condition]. Read it as a loop plus optional filtering. Dict and set comprehensions use braces with key:value or element expressions.

Nested comprehension clauses follow the same left-to-right order as nested loops. [x for row in matrix for x in row] flattens rows. A conditional expression before for transforms every item; an if after for filters items out.

enumerate supplies index-value pairs; zip aligns multiple iterables and by default stops at the shortest. zip(..., strict=True) (Python 3.10+) raises if lengths differ. Use unpacking instead of manually indexing parallel arrays when possible.

any short-circuits at the first true item; all at the first false item. any([]) is False and all([]) is True. sum can count Boolean predicates because True and False act as 1 and 0 in arithmetic.

values = [-2, -1, 0, 1, 2]

print([(i, value) for i, value in enumerate(["a", "b"], start=1)])

[(1, 'x'), (2, 'y')]

The first expression filters; the second maps all five inputs. zip creates only two pairs because one input ends.

02 · Iterators and generators

An iterable can provide an iterator with iter(). An iterator produces the next value with next() and raises StopIteration when exhausted. A list is reusable; a particular iterator is consumed as it advances.

A generator function contains yield. Calling it creates a generator without immediately executing the body. Each next resumes until the next yield; local state is suspended between yields. return ends iteration.

A generator expression uses parentheses and computes values lazily. This avoids materialising a large intermediate list when the consumer processes values one at a time. The source itself may still occupy memory.

map, filter, zip and enumerate produce lazy iterator objects in Python 3. Converting to list consumes them. To iterate twice, recreate the iterator or deliberately materialise it. Laziness also means errors may occur during consumption rather than construction.

def squares(n):
    for i in range(n):
        yield i * i
g = squares(4)
print(next(g))
print(list(g))
print(list(g))
it = iter([10, 20])
print(next(it), next(it), next(it, "done"))

Output:

0
[1, 4, 9]
[]
10 20 done

The first next consumes 0. list consumes the remaining three values. The exhausted generator subsequently produces no values. The default argument to next avoids StopIteration.

A generator is not an automatically reusable list. Saving it does not save all its produced values.

03 · Functions as values and stable sorting

Functions can be passed as arguments, returned, or stored in containers. lambda creates a function from one expression; def is clearer for multi-step logic. A key function transforms each item into the value used for ordering.

sorted returns a new list; list.sort mutates. Python sorting is stable: elements with equal keys retain their original relative order. A tuple key compares lexicographically, letting you express primary and secondary criteria.

To sort by descending score then ascending name, use key=lambda row: (-row[1], row[0]). reverse=True reverses the full ordering, which is different when only one criterion should descend.

min and max also accept key and, for an iterable, a default for empty input. Sorting all n elements to find one minimum does unnecessary O(n log n) work compared with one O(n) scan. Think about what result is actually required.

rows = [("Ira", 80), ("Dev", 90), ("Asha", 90)]
print(sorted(rows, key=lambda row: (-row[1], row[0])))
print(rows)
print(max(rows, key=lambda row: row[1]))
words = ["aa", "b", "cc", "d"]
print(sorted(words, key=len))

Output:

[('Asha', 90), ('Dev', 90), ('Ira', 80)]
[('Ira', 80), ('Dev', 90), ('Asha', 90)]
('Dev', 90)
['b', 'd', 'aa', 'cc']

Scores descend through negation, then names ascend. max returns the first maximum encountered. Stable sorting preserves b before d and aa before cc.

Build reliable programs

01 · Exceptions and debugging deliberately

Read a traceback from its final exception line, then inspect the relevant frames and source lines. SyntaxError concerns parsing; NameError an unresolved name; TypeError an unsuitable operation/type; ValueError an unsuitable value; IndexError an invalid sequence index; KeyError an absent mapping key.

try handles only exceptions raised in its suite. except should name the specific exceptions you can meaningfully handle. else runs when the try suite succeeds; finally runs during normal exit and exception unwinding. A return in finally can suppress an earlier return or exception and should generally be avoided.

raise communicates a failed contract. Use ValueError for an invalid value and TypeError for an incompatible type when writing a reusable API. Do not hide every error with except: pass; unexpected failures then become much harder to diagnose.

Debug systematically: reproduce with the smallest input, state the expected result, inspect intermediate values using repr, change one hypothesis at a time, and add a regression test. Assertions express programmer expectations, but may be removed in optimised execution; do not use them as the only validation for user input.

def parse_nonnegative(text):

    if value < 0:

    return value
for text in ["12", "oops", "-3"]:
    try:

invalid: oops

The second input fails conversion; the third fails the explicit range check. Both are handled as invalid user values.

02 · Tests and edge cases

A test compares observed behaviour to a specification. Include typical examples, boundaries, empty input, singleton input, duplicates, negative values, and invalid input where relevant. A function that passes one demonstration is not established as correct.

Use assertions for small development checks and unittest or another test runner for a growing project. Each test should be independent. Test returned values and intended mutation, not merely whether execution produces no exception.

Properties can catch errors beyond fixed examples: sorting should preserve length and element counts, reversing twice should recover the sequence, and normalising an already normalised value should leave it unchanged. Randomised tests can help, but use a seed for reproducibility.

Use a simple trusted method as an oracle for small inputs, then compare a faster implementation. Testing increases confidence; an invariant or proof explains why an algorithm works for all valid inputs. Both are useful for exam reasoning.

def unique_in_order(values):
    return list(dict.fromkeys(values))
cases = [([], []), ([1], [1]), ([2, 1, 2, 3, 1], [2, 1, 3])]

    assert values == before

A module is a Python file with its own namespace. import math binds the module name; from math import sqrt binds a particular attribute. Avoid wildcard imports because they obscure where names came from. Do not name your own file random.py or json.py when you need the standard module.

Objects & advanced tools

01 · Classes and independent state

A class defines a type whose instances combine state and behaviour. __init__ initialises a new instance; self refers to the instance receiving a method call. Calling item.method(x) supplies item as self automatically.

Instance attributes belong to one object; class attributes are shared through the class. Put per-instance mutable collections inside __init__. A shared class-level list can accidentally mix the state of every instance.

Methods can enforce invariants: a bank balance or queue length should stay valid after each operation. Python conventions such as a leading underscore communicate internal implementation details; they are not strict access-control barriers.

Use a class when related state and operations form a coherent concept. A simple transformation may be clearer as a function. For data records, dataclasses reduce boilerplate; a mutable dataclass field should use field(default_factory=list), not a shared list.

class StudyLog:
    def __init__(self, name):
        self.name = name
        self.minutes = []
    def add(self, minutes):
        if minutes < 0:
            raise ValueError("negative duration")
        self.minutes.append(minutes)
    def total(self):
        return sum(self.minutes)
a, b = StudyLog("Asha"), StudyLog("Dev")
a.add(25)
a.add(30)
print(a.total(), b.total())

55 0

Each constructor call creates a separate list. Adding to a does not change b. Methods protect the nonnegative-duration contract.

02 · Protocols, composition and inheritance

Python often cares about supported behaviour rather than an exact class. An iterable supplies iteration; a sized object supports len; a context manager supports with. This behavioural approach is often called duck typing.

Special methods let objects participate in language operations: __len__, __iter__, __repr__, __eq__, and others. Implement only meaningful operations and keep their contracts consistent. If you define equality for mutable objects, do not casually make them hashable.

Composition places one object inside another to reuse behaviour. Inheritance expresses an is-a relationship and lets subclasses override methods; super() follows the method resolution order. Prefer a simple design over a deep hierarchy.

Equality and identity remain different for objects. Unless a class defines value equality, two separately created instances typically compare unequal. dataclass can generate value-based comparison and a useful representation; frozen prevents normal field reassignment but is not deep immutability of nested objects.

from dataclasses import dataclass, field
@dataclass
class Playlist:
    name: str
    tracks: list = field(default_factory=list)
    def __len__(self):
        return len(self.tracks)
    def __iter__(self):
        return iter(self.tracks)
p = Playlist("Focus", ["alpha", "beta"])
print(len(p), list(p))
print(Playlist("Empty") == Playlist("Empty"))

len and list use the protocols implemented by the object. dataclass-generated equality compares fields of matching class instances.

03 · Decorators, context and advanced boundaries

A decorator takes a function (or class) and returns a replacement. @decorate above def f is roughly f = decorate(f). A wrapper can add timing, validation, logging or caching. functools.wraps preserves useful metadata of the wrapped function.

A closure lets the wrapper remember the original function. Accepting *args and **kwargs forwards a flexible signature. Always return the wrapped function’s result unless deliberately changing the contract.

A context manager brackets an operation with setup and cleanup. with is useful for files and resources; contextlib.contextmanager can implement one using a generator with a single yield and cleanup in finally.

Advanced Python also includes async/await, concurrency, descriptors and metaclasses. They are professional specialisations, not individually named DA programming subtopics. Reason about algorithms

01 · Time and space from code

Choose the input size first: n might be list length, number of vertices, or number of digits. Count dominant operations as a function of n. Big-O is an asymptotic upper bound; Theta is a tight growth bound; Omega is a lower bound. State best, average or worst case where needed.

Sequential loops add costs; nested loops do not always multiply by n blindly. A triangular loop has n(n-1)/2 iterations and is Theta(n²). A loop halving its positive integer counter has Theta(log n) iterations. An early return can make best and worst cases different.

Under the standard list model, indexing and len are O(1), append is amortised O(1), and front insertion/removal is O(n). A length-k slice allocates O(k) space and takes O(k) time. Membership in a list is O(n), whereas hash containers offer expected O(1) lookup with caveats.

Auxiliary space excludes the input unless stated otherwise. Include recursion stack and allocated slices. Complexity statements often assume constant-cost arithmetic on bounded-size values; Python’s arbitrary-precision integers can violate that assumption for huge numbers.

def operations(n):
    count = 0
    for i in range(n):
        for j in range(i):
            count += 1
    return count
for n in [0, 1, 4, 8]:
    print(n, operations(n), n * (n - 1) // 2)

Output:

0 0 0
1 0 0
4 6 6
8 28 28

Exact counts agree with the triangular-number formula. Doubling a large n approximately quadruples this count.

O(n²) does not mean exactly n² operations. Also, O(n) can be a valid but loose upper bound for an O(1) routine.

02 · Prefix sums and sliding windows

For repeated range-sum queries, precompute prefix[0]=0 and prefix[i+1]=prefix[i]+a[i]. Then the sum over the half-open interval [left,right) is prefix[right]-prefix[left]. Building costs O(n); each query costs O(1).

A fixed-width sliding window updates the previous sum by removing the outgoing value and adding the incoming value. This avoids recomputing each width-k sum from scratch. Keep the invariant that the variable equals the current window’s sum.

Validate k: it should be positive and no larger than the input length for the usual full-window problem. Initialise the best sum from the first real window rather than zero so all-negative inputs work.

Two pointers can also solve variable-window problems, but the rule for moving pointers needs a proof. For example, expanding a sum window is monotone for nonnegative values; negative values can invalidate a strategy that assumes every expansion increases the sum.

a = [2, -1, 4, 3, -2]
prefix = [0]
for x in a:
    prefix.append(prefix[-1] + x)
print(prefix)
print(prefix[4] - prefix[1])
k = 3
window = best = sum(a[:k])
for right in range(k, len(a)):
    window += a[right] - a[right-k]
    best = max(best, window)
print(best)

Output:

[0, 2, 1, 5, 8, 6]
6
6

The query covers a[1:4], whose sum is -1+4+3=6. Width-three sums are 5,6,5, so the maximum is 6.

A half-open [left,right) query excludes right. Prefix arrays have n+1 entries for this convention.

03 · Linear and binary search

Linear search examines elements until it finds a match. It works on unsorted sequences and costs O(n) in the worst case. Specify whether you want any occurrence, the first occurrence, or all occurrences.

Binary search needs an ordered search space and a predicate that divides it consistently. With half-open bounds [lo,hi), use mid=(lo+hi)//2 and discard a half while preserving the invariant that the answer lies in the retained interval.

A lower-bound search returns the first index where a[i]>=target. If all elements are smaller, it returns n. It handles duplicates naturally. Membership is then pos<n and a[pos]==target. bisect_left implements this position search in the standard library.

Each iteration shrinks the interval, giving O(log n) comparisons. Searching by slicing recursively can add copying costs; indices avoid this. Inserting into a list at the located position still takes O(n) shifting time.

def lower_bound(a, target):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo
a = [1, 3, 3, 7]
for target in [0, 3, 5, 9]:
    print(target, lower_bound(a, target))

Output:

0 0
3 1
5 3
9 4

For 3 the first eligible position is 1. For 5 it is 3, before 7. For 9 no eligible element exists, so return len(a)=4.

Binary search on unsorted data is not correct merely because the code terminates.

Data structures in Python

01 · Stack and queue behaviour

A stack is last-in, first-out. A list supports push via append and pop from the end. A queue is first-in, first-out; collections.deque supports append and popleft efficiently. Using list.pop(0) shifts remaining elements and costs O(n).

Stacks model pending work, undo history and matched delimiters. To check balanced parentheses, push opening symbols, and require each closing symbol to match the most recent opening one. At the end the stack must be empty.

Queues model tasks waiting in arrival order and breadth-first exploration. Always define what happens when removing from an empty container. For a bounded circular queue, head and tail indices wrap modulo capacity; distinguish full and empty states explicitly.

The abstract data type specifies behaviour; a representation implements it. A linked list or array can implement a stack or queue with different performance trade-offs. Do not confuse the FIFO/LIFO contract with one specific Python class.

from collections import deque
stack = []
stack.append("A"); stack.append("B")
print(stack.pop())
queue = deque(["A", "B"])
print(queue.popleft())
def balanced(text):
    stack, pairs = [], {')': '(', ']': '[', '}': '{'}
    for c in text:
        if c in "([{": stack.append(c)
        elif c in pairs:
            if not stack or stack.pop() != pairs[c]: return False
    return not stack
print(balanced("([{}])"), balanced("([)]"))

Output:

B
A
True False

A stack removes B because it arrived last; the queue removes A because it arrived first. The mismatched delimiter example fails when ) expects ( but [ is on top.

02 · Linked nodes and binary trees

A singly linked list stores a value and a reference to the next node. Accessing the k-th item requires following links, so it is O(k). Inserting after a known node is O(1); finding that node may cost O(n).

A binary tree has at most two children per node. Preorder visits root-left-right; inorder visits left-root-right; postorder visits left-right-root. These are recursive definitions that naturally map to call frames.

A binary search tree maintains an ordering rule: left keys are smaller and right keys larger, with a declared duplicate policy. Inorder traversal yields sorted keys. Search costs O(h), where h is height; a skewed tree may have h=O(n).

A heap is different from a BST: the parent priority is no greater than its children in a min-heap, but sibling/subtree keys are not globally ordered. heapq supports O(log n) push/pop and O(n) heap construction. These are bridges; full tree algorithms require additional deliberate practice.

class Node:
    def __init__(self, value, left=None, right=None):
        self.value, self.left, self.right = value, left, right
def inorder(node):
    if node is None:
        return []
    return inorder(node.left) + [node.value] + inorder(node.right)
root = Node(4, Node(2, Node(1), Node(3)), Node(6))
print(inorder(root))

Inorder recursively completes the left subtree before the root. heapify establishes the heap property, and repeated pops produce ascending values. The simple traversal uses concatenation for clarity; a generator avoids repeated list copies.

03 · Graphs, visited state and BFS

A graph consists of vertices and edges. An adjacency list maps each vertex to its neighbours and typically uses O(V+E) space; an adjacency matrix uses O(V²). Directed edges need not be symmetric; undirected edges appear in both adjacency lists.

Breadth-first search uses a queue and discovers vertices in distance layers. Mark a vertex visited when enqueuing, not only when removing it, to prevent duplicate work. In an unweighted graph, the first discovered distance is a shortest path length in number of edges.

Depth-first search explores deeply using recursion or an explicit stack. Both BFS and DFS need visited state for cyclic graphs. With adjacency lists they run in O(V+E) over the visited graph. Traversal order within a layer depends on neighbour order.

BFS does not solve arbitrary weighted shortest paths. Dijkstra requires nonnegative edge weights; negative weights need other reasoning. This lesson provides Python implementation literacy; the full graph/shortest-path syllabus remains a separate DSA study unit.

from collections import deque
graph = {'A': ['B', 'C'], 'B': ['A', 'D'], 'C': ['A', 'D'], 'D': ['B', 'C']}
def bfs(graph, start):
    distance, queue = {start: 0}, deque([start])
    while queue:
        u = queue.popleft()
        for v in graph[u]:
            if v not in distance:
                distance[v] = distance[u] + 1
                queue.append(v)
    return distance
print(bfs(graph, 'A'))

Output:

{'A': 0, 'B': 1, 'C': 1, 'D': 2}

A discovers B and C at distance 1. B discovers D at distance 2. When C sees D, it is already recorded and is not enqueued again.

A graph may be disconnected. A traversal from one start visits only its reachable component.

def analyse(rows):
    totals, rejected = {}, []
    for i, row in enumerate(rows):
        topic, minutes = row.get('topic'), row.get('minutes')

Goal: extract words, count them, and display a deterministic top-k report. Decide what a word means. This example uses runs of ASCII letters for an explicitly English-only input contract; multilingual tokenisation requires a different policy.

import re
from collections import Counter
def top_words(text, k=3):
    if k < 0:
        raise ValueError('negative k')
    tokens = re.findall(r'[a-z]+', text.casefold())
    counts = Counter(tokens)
    return sorted(counts.items(), key=lambda item: (-item[1], item[0]))[:k]
print(top_words('Learn Python. Learn by doing. Python helps!', 3))

Output:

[('learn', 2), ('python', 2), ('by', 1)]

learn and python tie at count 2 and sort alphabetically. The one-count words follow, with by first alphabetically.
